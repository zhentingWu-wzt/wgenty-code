# 四向同步规范（PRD / Jira / 代码 / 用例）

## 核心原则

PRD 是唯一权威源（SSOT）。一次需求变更 = 修改 PRD 一次 + 三次单向投影（Jira、代码、用例）。禁止反向写入，禁止四方对等互改。

## 适用范围

- 适用于：任何影响行为的需求变更，包括小需求和缺陷修复
- 不适用于：不改行为的重构、纯文案笔误（记入 Jira 即可，不动 PRD）

## 同步链（按序执行，单向流动）

| 步骤 | 动作 | 产出与留痕 |
|---|---|---|
| 1 | 更新 PRD（唯一变更入口），走变更评审 | PRD 版本号递增 + 评审记录 |
| 2 | 更新 Jira ticket：验收标准与 PRD 对齐 | ticket 引用 PRD 版本号 |
| 3 | 提交代码：MR 引用 ticket ID | MR 标题含 `[KEY-123]` |
| 4 | 更新 Xray 用例：挂 ticket，逐条覆盖验收标准 | 用例 ID 回写到 ticket |

## 硬门禁（任一不满足则不准合入）

1. MR 未引用 ticket → 不准合入
2. ticket 验收标准未与最新 PRD 版本对齐 → 不准进入 UAT
3. Xray 用例未逐条覆盖验收标准 → 不算 Done
4. PRD 无版本记录（变更未留痕）→ 整条同步链无效

## 冲突仲裁

- 任何一方与 PRD 冲突时，以 PRD 为准。PRD 本身错了 → 先改 PRD 并重新评审，再重新投影；禁止就地修改投影方。
- 紧急线上修复例外：允许先合入并补 ticket，但 24 小时内回补 PRD 与用例；回补完成前 ticket 保持 OPEN。

## 禁止事项

- 禁止把 PRD 正文整段复制到 Jira 或 MR——引用链接，不复制内容，副本必然腐烂
- 禁止在 Jira 中直接修改需求内容，Jira 只承载状态流转和验收标准引用
- 禁止跳过步骤 1 直接改代码（紧急例外见上）

## 角色分工

| 角色 | 职责 |
|---|---|
| 上下文所有者（BA 或 PO 指定一人） | PRD 更新、组织变更评审 |
| DEV | MR 与 ticket 的双向关联 |
| QA | 用例覆盖验收标准、用例 ID 回写 |

## 度量（每迭代复盘）

- 同步合规率：满足全部 4 条硬门禁的变更占比
- spec churn：PRD 在评审通过后的修改次数（衡量 Align 质量）

## 常见错误

| 错误 | 后果 | 纠正 |
|---|---|---|
| 先改代码再补 PRD | 投影失去源头，验收标准漂移 | 回滚代码，或立即补 PRD 评审 |
| 在 Jira 里直接改需求 | 出现第二权威源 | 恢复 Jira 原文，改 PRD 后重新投影 |
| 用例只挂需求不覆盖验收标准 | 假覆盖，UAT 漏测 | 按硬门禁 3 打回 |
| 复制 PRD 内容到 ticket | 内容分叉，版本失控 | 删除副本，改为链接引用 |
