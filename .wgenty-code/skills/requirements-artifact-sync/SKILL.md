# 需求层制品同步（PRD / 原型 / Figma / 用例）

## 核心原则

PRD 的验收标准（AC）是唯一权威源。**AC-ID 是四方关联键**：原型屏、Figma frame、Xray 用例都标注自己覆盖的 AC-ID。一次需求变更 = 修改受影响的 AC + 按影响面更新三方投影。

交付层同步（PRD / Jira / 代码 / 用例）见 skill：`four-way-sync`。本 skill 只管需求门禁之前的需求层。

## 信息所有权（每类信息只有一个家）

| 载体 | 拥有（权威） | 只做引用 |
|---|---|---|
| PRD | 业务意图、范围、验收标准 | 原型/Figma 链接 |
| 原型 | 交互流程的探索态草稿 | 行为定义以 PRD 为准 |
| Figma | 视觉与交互定稿 | 用标注挂覆盖的 AC-ID |
| Xray 用例 | 测试步骤与数据 | covers 逐条覆盖 AC-ID |

## AC-ID 规范

- 格式：`AC-001`、`AC-002`……PRD 内全局唯一，编号只增不复用（废弃标记为 VOID，不删除）
- Figma frame / 原型屏：标注覆盖的 AC-ID
- Xray 用例：用例字段或 “covers issue” 挂 AC-ID
- 禁止把 AC 正文复制进 Figma 或用例——挂 ID，比对交给 AI

## 变更流程

1. **AI 影响分析**：diff 出新增/修改/废弃的 AC 集合，反查波及的原型屏、Figma frame、用例，输出影响面清单；发现歧义就地提问，确认后继续
2. **人确认影响面**（唯一审批关口）
3. **更新 PRD 的 AC**（唯一内容变更入口，版本号递增，版本历史记录变更的 AC-ID）
4. **AI 生成投影 delta**：Figma 波及 frame 清单（视觉定稿由设计师改）、原型需更新屏、Xray 用例增删改草稿——分发责任人，确认后落库
5. **AI 一致性校验**：每条 AC 是否有 Figma 覆盖、用例覆盖，语义是否一致；报告通过才过需求门禁

## 关键规则

- **原型可先行，门禁前回流**：原型允许先于 PRD 演化（BA 探索交互），但过需求门禁前必须把交互结论回流进 PRD 的 AC；未回流的交互细节不算数
- **原型非强制**：交互复杂的需求（新流程、多状态页面）必须出原型；简单 CRUD 直接出 Figma，跳过原型环节
- **工具归一**：原型放在 Figma 生态（低保真流），链接、标注、AC-ID 同一平台；不单独引入 Axure/墨刀等第二工具

## 一致性门禁（过需求门禁的必要条件）

1. 每条非 VOID 的 AC 均有 Figma frame 覆盖（标注 AC-ID）
2. 每条非 VOID 的 AC 均有 Xray 用例覆盖（covers AC-ID）
3. AI 语义比对报告无未处理的红旗项
4. 原型与 PRD 冲突的交互结论已回流（原型不再持有未回流的权威信息）

## 角色分工

| 角色 | 职责 |
|---|---|
| BA | PRD 与 AC 维护、原型探索与回流 |
| 设计师 | Figma 定稿与 AC-ID 标注 |
| QA | Xray 用例覆盖与 AC-ID 关联 |
| AI | 影响面分析、投影 delta 草稿、一致性报告（只提议，不直接落库） |

## 分阶段引入

1. 第 1 周：定 AC-ID 规范，启用带 AC 区块的 PRD 模板（见 `prd-template.md`）
2. 第 1 迭代：只为新需求和 top 20 活跃需求打 ID，存量不回填
3. 第 2 迭代：门禁时跑 AI 只读一致性报告（不改任何东西，先建立信任）
4. 第 3 迭代起：影响面分析 + 投影 delta 生成上线，人工确认后落库

## 常见错误

| 错误 | 后果 | 纠正 |
|---|---|---|
| AC 不编号 | 四方无关联键，AI 比对退化为全文猜测 | 退回 PRD 补 ID 后再同步 |
| 复制 AC 正文到 Figma/用例 | 副本腐烂，改一处漏三处 | 删正文，只挂 ID |
| 原型结论不回流 PRD | 原型变成隐形权威源 | 门禁 4 拦截，回流后再过 |
| 废弃的 AC 直接删除 | 历史用例失去指向，追溯断链 | 标记 VOID 保留编号 |
| AI 直接改 Figma/用例落库 | 幻觉写入生产制品 | 写路径必须人确认后执行 |
