01

厂商分组配置与安全迁移

原来

每个旧 profile 重复保存厂商连接信息，平铺列表难以维护。

现在

providers 按厂商保存共享连接信息和模型列表；旧 profiles 自动聚合，写回前备份，冲突时保留旧文件并报错。

原因 减少重复配置，同时避免同名端点冲突造成静默数据丢失。

修改src/config/models.rs
ProviderGroup / ProviderModel / resolve_endpoint / migrate_providers
修改src/config/tests.rs
迁移幂等、key 优先级、冲突保留旧文件与 planner reload 测试
02

会话级模型和权限

原来

模型和权限主要由全局或 project 状态决定，并行会话会互相影响。

现在

Session 保存可选覆盖；每个轮次和 subagent spawn 解析自己的快照，支持重置，Plan 仅保留在当前进程而落盘为 derived。

原因 让同 project 的多会话独立选择模型和权限，并保持重启后的安全语义。

查看文件和关键代码 3
修改src/daemon/state.rs
resolve_session_model + effective_permission + provider-scoped spawn settings
修改src/context/memory_session.rs
原子字段更新；运行时 Plan 与持久化 derived 分离
修改src/daemon/handlers/tools.rs
旧 /tools/execute 同样使用 effective_permission(session_id)
03

动态模型目录

原来

选择器只能依赖手工模型和静态列表，厂商端点挂起会阻塞目录。

现在

动态、手工和内置目录按名称合并，缓存 5 分钟；单厂商拉取 250ms 超时，多厂商并发；不可用 session override 失败关闭。

原因 模型列表更完整，同时保证网络故障时手工模型仍可见、可切换且不会误用其他厂商。

ModelCatalogService：三级合并、TTL、单飞、timeout
修改src/daemon/handlers/system.rs
GET /models 原地合并；join_all 并发目录请求
其余变化 (1)
04

Web 两级 chips 与状态同步

原来

模型和权限入口位于底部 StatusBar，Web 状态不是完整的 per-session 结构。

现在

Composer 上方提供厂商→模型两级 chip 和权限 chip；StatusBar 保留连接、审批和用量信息，事件、请求和重连按 session 隔离。

原因 入口位置与作用域一致，避免并行会话串扰及旧响应覆盖新事件。

两级 picker、Follow default、revision-gated mutations
修改web/src/state/sessionManager.ts
per-entry model/mode、revision 与 request generation
修改web/src/components/StatusBar.tsx
删除模型和权限控件
